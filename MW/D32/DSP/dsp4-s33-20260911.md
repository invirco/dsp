## 1. Gate 1 — `shipping.config.s32`, written and built twice

### 1.1 The file is s26 plus one line, and the diff says so

`MW/D32/DSP/SHARC/shipping.config.s32` is `shipping.config.s26` **verbatim**,
with a header above it and one entry below it. Stripped of comments and
blank lines the whole difference is:

```
$ diff <(grep -vE '^\s*#|^\s*$' shipping.config.s26) \
       <(grep -vE '^\s*#|^\s*$' shipping.config.s32)
22a23
> DSP4_AUXIN_BYPASS=1
```

**Twenty-three switch positions, twenty-two of them s26's own.** The
operating point is not touched: `DSP4_GEN_BLOCK=16`, `DSP4_BLOCK_KERNELS=1`,
`DSP4_CCLK_TARGET=983`, `DSP4_SHARED_KERNELS=15`, `DSP4_TX_EARLY=2` and the
rest are byte-for-byte s26's.

### 1.2 The twelve nodes and their host cells

The flag reaches exactly twelve chip-2 `AUX_INPUT` nodes. Chip 1 carries
none of the class, which is why its image cannot move — and does not (§1.4).

| node | `on` cell | DSP address of `on` | input | `on` at boot |
|---|---|---|---|---|
| `C2_SNK_IN_01..08` | `Snk[1-8]On` | 0x0746, 0x0748 … 0x0754 | `C2_XR_SNAKE_01..08` | 0 |
| `C2_CODEC_AUX_IN` | `CodecAux001On` | 0x0742 | `C2_XR_CODEC_AUX_L` | 0 |
| `C2_PI_IN` | `Pi001On` | 0x0744 | `C2_XR_PI_L` | 0 |
| `C2_USB_IN` | `Usb001On` | 0x0706 | — (no wired source) | 0 |
| `C2_BT_IN` | `Bt001On` | 0x0708 | — (no wired source) | 0 |

Every one is an ordinary host-written parameter cell in
`chip2/dsp_params.asm`'s dispatch table — the gate's first test reads the
same word the app writes, with no config word and no commit in between.

### 1.3 The generated gate, reviewed again against S32-2

Read out of the emitted source rather than off the design note. The **park**,
in each node's own body (`C2_PI_IN.asm`, and the same eleven lines in the
other eleven):

```
    /* ---- PARK: _auxin_on_C2_PI_IN is off ---- */
    r5 = dm(_auxin_on_C2_PI_IN);
    r5 = pass r5;
    if ne jump (pc, .bwrun_C2_PI_IN);
    r0 = 1;
    dm(_auxin_byp_C2_PI_IN) = r0;          /* the flag the chain reads   */
    l0 = 0;  r0 = 0;  i0 = _blk_C2_PI_IN;
    lcntr = DSP4_BLOCK_SIZE, do .bwpk_C2_PI_IN until lce;
    .bwpk_C2_PI_IN: dm(i0, 1) = r0;        /* ONE block of zeros         */
    dm(_buf_C2_PI_IN) = r0;
    rts;
```

and the **chain gate**, six instructions, at the call site:

```
    /* C2_PI_IN: skip while `on` is 0 and the block is already silent */
    r2 = dm(_auxin_on_C2_PI_IN);
    r2 = pass r2;
    if ne jump (pc, .c2brunabC2_PI_IN_run);    /* on -> always call      */
    r2 = dm(_auxin_byp_C2_PI_IN);
    r2 = pass r2;
    if ne jump (pc, .c2brunabC2_PI_IN_end);    /* off AND parked -> skip */
.c2brunabC2_PI_IN_run:
```

**The order S32-2 designed is the order that is emitted.** `on = 0` and not
yet parked ⇒ the node IS called, parks, publishes zeros, raises the flag;
`on = 0` and parked ⇒ skipped; `on = 1` ⇒ called, whatever the flag says,
because the gate's first test is the host's own cell. So a 0 → 1 flip takes
effect **on its own block**, and a 1 → 0 flip costs exactly one more call.

**The gate is emitted in all three chain orderings, and this was checked
rather than taken from S32's note.** `chip2/process_chain.asm` carries three
copies of the chain under different preprocessor arms, and each copy carries
twelve gate sites under its own label prefix:

| ordering | label prefix | gate sites |
|---|---|--:|
| block-ordered (`DSP4_C2_BQ_PAIRED_GRAPH`) | `.c2brunab*` | **12** |
| graph-ordered, same arm | `.c2grunab*` | **12** |
| the `#else` arm | `.sgrunab*` | **12** |

Nothing is left ungated, so a configuration change that selects a different
ordering cannot silently drop the saving.

**`C2_USB_IN` and `C2_BT_IN` are the two the generator REORDERS** ahead of
`C2_MIX_MAIN_L/R` (`dsp_validate`'s four standing process-order notes), and
the gate travels with them: it is emitted around the moved call site, not
around the position the CSV lists.

### 3.2 How the worst block is read, and one thing that had to be fixed to read it

Average % of budget / worst block, mean of the two boots, 270,096 blocks a
row. The worst-block column is, in order of preference:

1. the tool's S21-6 **de-ticked** figure where it supplies one;
2. otherwise the part's own `proc_cyc_max_pct`, where that is under 150 % of
   budget;
3. otherwise `proc_cyc_max_after_clear`.

**Step 3 is needed, and it is needed on exactly the rows this decision turns
on.** S21-6's de-tick is gated on `overruns == 0` — rightly, since a genuine
four-times-budget pass drops three blocks — so **candidate A's overrunning
rows get no correction at all**, and three of the six came back with a raw
latch of 400.6 % (one whole `TPERIOD` of 983,040 cycles, S21-6's signature)
sitting beside an average of 100.86 %. `proc_cyc_max_after_clear` is a second,
independent latch read over a short window after the dwell's clear; across
all twelve D32 chip-2 rows of both arms it lands within **0.3 points** of the
de-ticked or sane figure every time. The rule is applied **identically to
both arms**, and it is used on three candidate-A rows and one candidate-B row
(§7, S33-6).

candidate B is not also a decision that banks S29's 3.5 points — it is the
same five points, taken without costing the product a feature (§7, S33-7).

## 4. Gate 4 — the latency bar and the flip

### 4.1 The latency bar was NOT REACHED, and the reason is a bench rule

**It is not a failure and it is not a skip: the bar and this session's bench
rules do not compose, for the second session running.**

S29's method needs **two CPLD bitstreams** — `maincap` for the through-DSP
arm and `pisel` for the CPLD-loop reference that the 82 samples are measured
*against* — and this dispatch says, in as many words, **do not reflash the
CPLD**, because the analog board may be attached and the 74HC595 chain is
never to be approached. A CPLD reconfiguration tri-states the lanes that
chain sits on for the length of an SVF, which is the hazard the rule exists
for. **The CPLD was not touched**: `./loadlogic.sh --id` gave no reply — the
shipping bitstream, exactly as S31 and S32 left it — and no flash was
attempted.

**What can honestly be said without the measurement**, and it is an argument,
not a number:

* Through-DSP latency on this platform is set by the block size and
  `DSP4_TX_EARLY`. Candidate B's `shipping.config.s32` carries
  `DSP4_GEN_BLOCK=16` and `DSP4_TX_EARLY=2`, byte-identical to candidate A's
  (§1.1), and `DIAG_BUILD_CFG` reads `0xCF45FF10` on both (§5.2).
* The gate changes **which nodes are called**, not when the transmit
  happens, and chip 1 — which owns the input half of the path — is
  byte-identical between the candidates.
* S29 measured **82 / 82 / 81 samples** on candidate A, n=3 boots × 20 reps,
  100.0 % coherent, and that figure reproduces S17's and S11's.

**So the contract figure of 82 samples / 1.708 ms stands where S29 measured
it, on candidate A, and candidate B has no measurement of its own.** That is
the one bar in candidate A's set that candidate B does not carry, and it is
recorded as a gap rather than argued away (§7, S33-5).


### 4.2 The flip, repeated on the final bytes — 25 of 30 checks, and the five failures are S32-3

`tools/pi/dsp4_s32_flip.py` on the **candidate-B image the §3 rows were taken
on** (`6396187c` / `df5cc181`, booted from `/home/app/dspcap/s33b`, the CM4
playing a 400 Hz full-scale square), five nodes, `on` flipped 0 → 1 → 0 one at
a time, with the node's own state and its published block read back out of
the part at every step.

**`C2_PI_IN` — the audio witness, at full scale:**

| | `_auxin_on_` | `_auxin_byp_` | `_auxin_q_` | `_blk_C2_PI_IN` |
|---|--:|--:|--:|---|
| off (as booted) | 0 | **1** | `0x00000000` | **all zero** |
| **on** | 1 | **0** | `0x10000000` | `0x0fffffff 0xf0000000 0x0fffffff …` — its input, at unity |
| off again | 0 | **1** | `0x10000000` | **all zero** |

**A node the chain had not called since boot passes full-scale audio at unity
on the block its cell goes to 1, and publishes exact silence the moment it
goes back to 0.** No partial block, no ramp-in, no gap. The four snake returns
`C2_SNK_IN_01..04` behave identically on the state witness: `byp` set while
off, cleared on the block the node runs again, the block carrying their input
(`0xffffffff`) at unity when on and all zero when off.

**Per node: 5 of 6 checks PASS; 25 of 30 across the five.** The one that fails
on every node is S32-3 and nothing else: `_auxin_q_` still holds `0x10000000`
after the node goes back off, because the park returns before the body and the
control-rate section that recomputes the coefficient never runs. It cannot
reach the audio — the sample path executes only on blocks where the node is
called and NOT parked, and sample 0 recomputes `q` before the first MAC — and
the published block is exact zero either way, on all sixteen words of all five
nodes. **The fix is one instruction and is deliberately not made** (§5.3,
`window-candidate.md` §5.4).

This is S32's gate-4 result reproduced check for check on the bytes this
session measured, which is what the dispatch asked for.

Report: `goldens/s33-flip-candB.json`; runners `s33flip.sh` /
`s33flip_run.sh`.

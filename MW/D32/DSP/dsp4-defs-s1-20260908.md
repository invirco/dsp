# defs S1 — this repo becomes a consumer of `invirco/defs`

Contract: **defs-v2026.09.08**, submodule commit `b0e4b487fdca25d6e4558dc953d7400aef13d686`.
Desk work only — the rev C unit and the bench were not touched.

## 1. What was wrong

`sync-from-mx26.sh` copied six definition CSVs out of an mx26 checkout,
expanded the two mx-masters with mx26's expander, and then ran
`prune-compat-aliases.py` over the result — which **deleted whole cell
families and renumbered `MxAdd` behind them**. The output was a matrix
generation of this repo's own making: D24 fingerprinted `b4592dfb639e`,
which is neither the tag `defs.lock` pinned (`85102bd3097d`) nor the hub's
current expansion (`7322e9a88b18`).

Two more copies did the same thing more quietly:
`docs/contract/{d24,d32}-wire-table.csv` and `docs/contract/wire-units.csv`
were distribution copies of mx26's generated tables, and
`shared/mx_master.csv` was a 287-row copy of the 508-row cell master, still
spelling the retired `Aa` prefix and read by nothing.

## 2. What replaced it

`defs/` is a submodule pinned to `defs-v2026.09.08`. `sync-defs.sh`

1. checks the submodule working tree against the gitlink this repo records,
2. requires the pin to carry a real `defs-v*` tag,
3. hashes the whole defs content manifest (`defs/tools/defs-manifest.sh`)
   and each declaration this repo reads, against `defs.lock`,
4. re-expands `MW/<P>/MX/_matrix.csv` with `defs/tools/expand_matrix.py`
   and verifies both the file hash and the matrix generation id.

Nothing else touches the expansion. The DSP address columns
(`DspSpi`/`DspPage`/`DspAdd`/`DspAddHex`/`Table`/`Ramp*`) remain a
consumer-side derived table written by `gen_dsp.py --force`, and
`audit-compat-aliases.py` now exists to prove exactly that: it re-expands
from defs and diffs every non-backfill column against what is in the tree.
Both products read **UNTOUCHED**.

Deleted: `sync-from-mx26.sh`, `prune-compat-aliases.py`,
`alias-retire-families.txt`, `MW/D2{4,4}/DEFS/*.csv`, `MW/D*/FW/fw.csv`,
`MW/D*/MX/*-mx-master.csv`, `docs/contract/*-wire-table.csv`,
`docs/contract/wire-units.csv`, `shared/mx_master.csv`.

## 4. The name changes, and every hand-written reference that broke

The pin jumps from `defs-v2026.08.20` to `defs-v2026.09.08`. D24 goes 5125
rows to 4946, D32 6940 to 6948, and **2,858 of D32's cell names change**.

| change | what broke | fix |
|---|---|---|
| `Aa*`/`Zz*` sort prefixes purged | `gen_dsp.py` mapped meter nodes to `AaChan`/`AaAux`/`AaGrp`/`AaFx`/`AaMain`/`AaSub`; `expand_meter` branched on `cat == 'AaChan'`; `wire_contract.py` tried `name` and `'Aa' + name` at three sites; `mcu-only-prefixes.txt` carried `Zz` | meters map to the strip's own category (`Chan`, `Aux`, `Grp`, `Fx`); `expand_meter` now branches on the node's own `taps=` declaration, which is what actually decides the layout; the `Aa` candidates and the `Zz` prefix are gone |
| `Rtg` infix retired (`RtgLevel`→`Level`, `RtgFx`→`FxOn`, `Rtg`→`Dest`, …) | `master_names.MASTER_RENAME_2026_08_25` and every lookup through it — `gen_dsp.py::_matrix_key`, its rename-reaches-nothing guard, `validate()`'s two-spelling reporting, `wire_contract.py::current_name` and its `'Rtg' in name` family key | the whole table is **deleted**. A generated cell now resolves by its own name or not at all. The guard that protected `--force` survives in a form that has nothing to do with renames: a generated cell FAMILY that reaches no matrix row is reported, because `--force` would otherwise clear the DSP columns of rows it merely failed to find |
| main section model: `Main[1-4]` output zones + a separate `Sub` strip become `Main` (the L/R bus) + `MainL`/`MainR`/`MainSub` | `C2_SUB_*` mapped to `Sub`; `C2_MAIN_O{EQ,COMP,LIM}_0N` and `C2_MTR_MAIN_0N` mapped to `Main` instance N; `C2_MAIN_XOVER` emitted `Main001Crossover*` | `C2_SUB_*` → `MainSub` (the master notes came across verbatim: "Subwoofer compressor attack"); outputs 1 and 2 → `MainL`, `MainR`; outputs 3 and 4 → **no master strip, reported**; the crossover emits its two cells for all three strips at the one address it actually has |
| `DcaOn` family | nothing — it was already host-managed by ruling, and now has 58 matrix rows instead of 0 | none needed; `validate()` reports 58/58 |
| `Main001Out3Mode001` (D24) carries a digit inside the suffix | `master_names.CELL_RE`'s letters-only suffix class silently classified it as "not cell-shaped" | suffix class widened to `[A-Za-z][A-Za-z0-9]*` |

`prune-compat-aliases.py` and `audit-compat-aliases.py` were the tools the
dispatch named for this. The prune step is retired outright; the audit was
rewritten around the question that replaced it.

## 5. Two findings

**F1 — the graph has four main outputs and the masters have three.** This
is review finding D52, and S1 makes it loud rather than resolving it:
`C2_MAIN_{OEQ,OCOMP,OLIM}_{03,04}` and `C2_MTR_MAIN_{03,04}` hold SPI
addresses and reach no master cell at all, and the main BUS compressor and
limiter (`C2_MAIN_COMP`, `C2_MAIN_LIM`) emit 21 cells the masters no longer
carry, having moved output dynamics onto the per-output strips. `gen_dsp.py`
now names all eight nodes and all 23 cells. **This is dsp.csv's to resolve
and the S1 dispatch bounds this session out of authoring it.**

**F2 — two families the prune step called aliases are back in the
definitions.** `FxDuckThr` (6 rows) now sits alongside `FxDuckSens` (6
rows), and `PeqGain` (12 rows each) sits on `MainL` and `MainR` alongside
`Main`'s 28-band `Geq`. They were pruned as compatibility aliases in July;
defs carries them, so they are definitions. Neither reaches a DSP address.
Recorded in `alias-audit.md`; whether they are intended is a hub question.

## 7. What is NOT claimed

- **No bench, by dispatch.** `busgold.sh`, `conform.sh` and every other
  on-part bar were not run. For `busgold` specifically the result cannot
  have moved: the audio image is byte-identical on both chips in all four
  arms, so there is no build for a capture to disagree with. The other
  on-part bars are simply not evidence this session has.
- **The MCU side changed and was not built.** H1S1 was not compiled here.
  `ghost_cells.c` goes 5,481 to 5,416 entries — 340 names out, 275 in.
  Almost all of that is the rename (`AaChan001Mtr001` out, `Chan001Mtr001`
  in, and so on for every meter); the net −65 is the main section, where
  the graph's four output zones stop emitting `Main00{1,2,3,4}Eq*` and emit
  `MainL`/`MainR` only, outputs 3 and 4 having no master strip.
  `mx_dsp_map.h` goes 3,417 to 5,393 entries, and that is not a new
  feature: the map keys matrix rows to ghost-cell indices by NAME, so the
  2,064 rows the old pin spelled `Chan001RtgMute001` while the ghost table
  spelled `Chan001Mute001` had no entry at all. **The H1S1 firmware could
  not dispatch to them.** One spelling closes that.
- **`check-contract-drift.sh --strict` cannot pass until this lands.** It
  compares against `git status`, and every generated artefact in this
  session is a pending change. It passes on the committed tree.
- **`MW/D24/DSP/SHARC/dsp.csv` still fails `dsp_validate.py`** with three
  pre-existing parameter errors (`source_gains` on two MIX_BUS rows,
  `dry`/`wet`/`width` on `C2_REVERB`). Untouched by this session; D24's
  SHARC tree lags D32 as recorded.

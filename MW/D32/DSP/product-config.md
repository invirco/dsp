# DSP4 product configuration (boot-time, decision D3)

One firmware image serves D24 and D32. At boot the Pi/CM4 host (D1)
configures each DSP over the normal SPI parameter protocol using the
register block below, then commits. Until CONFIG_COMMIT arrives, the main
loop waits (`_boot_config_received`) and no audio processing runs.

Implementation: `SHARC/src/product_config.asm` (hand infra) +
`SHARC/src/chip*/scope_gates.asm` and the RX patch machinery in
`SHARC/src/chip1/block_io.asm` (both generated by `tools/dsp/dsp_codegen.py`
from `scope=` params in dsp.csv).

## Register block (flat SPI address space, both chips)

| Addr | Name | Semantics |
|---|---|---|
| 0xF000 | PRODUCT_ID | 0 = D32 (default), 1 = D24 |
| 0xF001 | CHAN_MASK | active input strips, bit n = strip n+1 |
| 0xF002 | AUX_MASK | active aux buses |
| 0xF003 | OUT_MUX | bit 0: B_O2 content — 0 = D24 codec, 1 = D32 snake. Stored only; the snake output patch is not generated yet and the TX gather must consume this when it lands |
| 0xF004 | CONFIG_COMMIT | write 1: apply input patch + scope gates, release boot |
| 0xF010+ | INPUT_PATCH[i] | chip 1 only; one register per packed RX channel `i` (see below) |

Addresses ≥ 0xF000 are routed to `_product_config_write` before the
parameter dispatch; parameter writes are bounds-checked against the
generated `_spi_dispatch_cN_size` (fixes the former hardcoded 3904/1820
bounds that rejected newer parameters).

Scope gates: nodes with `scope=D24`/`scope=D32` params and a runtime
enable (today: the AUX_INPUT snake returns) are force-disabled at commit
when PRODUCT_ID differs. Product ids in `scope_gates.asm` and
`product_config.asm` must match (0=D32, 1=D24).

## Boot sequence (per chip, from the Pi)

1. Load DSP boot image over SPI slave boot (BMODE=SPI2 slave).
2. Write PRODUCT_ID, CHAN_MASK, AUX_MASK, OUT_MUX; on chip 1 write the
   INPUT_PATCH table if not identity.
3. Write CONFIG_COMMIT = 1.
4. Stream normal parameter state (scenes, levels) — the DSP is running.

## INPUT_PATCH semantics

`INPUT_PATCH[i] = j` means packed RX DMA channel `i` is delivered to the
slot variable that channel `j` feeds by default (identity when `i == j`).
Packed RX channel order is the block_io sort: (sport, slot) — IN_01..IN_32
are indices 0-31, then codec return (32-34), Pi PCM (35-36), MEMS (37),
snake (38-45). Out-of-range values clamp.

### D24 preset

D24's analog boards interleave console channels across the three fitted
ADC8s (hardware-map.md): AD0 carries ch 1-4 & 13-16, AD1 ch 5-8 & 17-20,
AD2 ch 9-12 & 21-24. AD3 has no D24 ADC (NET-only). The patch below maps
each packed DMA channel to the console strip that should receive it
(strip k is default index k-1):

| DMA ch (lane/slot) | Console ch | INPUT_PATCH[i] |
|---|---|---|
| 0-3 (AD0 s0-3) | 1-4 | 0,1,2,3 |
| 4-7 (AD0 s4-7) | 13-16 | 12,13,14,15 |
| 8-11 (AD1 s0-3) | 5-8 | 4,5,6,7 |
| 12-15 (AD1 s4-7) | 17-20 | 16,17,18,19 |
| 16-19 (AD2 s0-3) | 9-12 | 8,9,10,11 |
| 20-23 (AD2 s4-7) | 21-24 | 20,21,22,23 |
| 24-31 (AD3) | NET returns 25-32 | 24..31 (identity) |
| 32-45 | superset sources | identity |

D24 also boots CHAN_MASK = 0x00FFFFFF (strips 25-32 unused unless NET
sources are patched in).

NOTE: verify the within-ADC8 slot order (ch 1-4 on slots 0-3 vs
interleaved) against the D24 Analog rev B converter wiring before
bring-up; the table assumes block order per the hardware map reading.

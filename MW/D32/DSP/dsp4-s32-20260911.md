Session 32, 2026-09-11. Bench: rev C unit, `app@192.168.1.219`.

(`chip1.ldr 6396187c`, `chip2.ldr 9222c2ee`).

## 1. Gate 1 — the gate, designed on paper first

### 1.1 Where an AUX_INPUT is called, and what it costs to call it

Chip 2 carries **twelve** `AUX_INPUT` nodes and chip 1 carries none:

| node | cells | input | `on` at boot |
|---|---|---|---|
| `C2_SNK_IN_01..08` | `Snk[1-8]Level/On` (1861–1876) | `C2_XR_SNAKE_01..08` | 0 |
| `C2_CODEC_AUX_IN` | `CodecAux001Level/On` (1857–1858) | `C2_XR_CODEC_AUX_L` | 0 |
| `C2_PI_IN` | `Pi001Level/On` (1859–1860) | `C2_XR_PI_L` | 0 |
| `C2_USB_IN` | `Usb001Level/On` (1797–1798) | — | 0 |
| `C2_BT_IN` | `Bt001Level/On` (1799–1800) | — | 0 |

Every one of them comes up **off** in `dsp.csv`, and
`dsp4_driven_setup.py`'s `FAM_CLASS` filter keeps the `On` family to
`FX_ENGINE`, so **no capacity row this programme has ever taken turns any of
the twelve on**. They are called on every block regardless, three times over
in the generated chain (the strip-ordered chain, chip 2's pair-ordered chain
and the scalar chain), at

```
  chip2/process_chain.asm:994, 3621, 6278   (C2_SNK_IN_01 in each ordering)
```

and what the call buys, with `on = 0`, is arithmetic that is zero by
construction: the node's block wrapper stages BLOCK samples one at a time
through the scalar `_buf_` words, calls the per-sample body for each, and
the body multiplies each sample by `_auxin_q_`, which the `on` cell has
already forced to **exactly zero** (`if eq r1 = r3` in the control-rate
section). Sixteen samples of `x * 0`, with two call/rts pairs apiece.

**The per-node price, counted off the emitted code** at BLOCK 16, with the
call/rts pair at the 15.04 cycles measured on this part on 2026-08-30 and
one cycle an instruction:

| | cycles |
|---|--:|
| wrapper prologue / epilogue | 15 |
| per sample: 12 staging instructions | 12 |
| per sample: call/rts into the body | 15.04 |
| per sample: block-rate guard + taken branch | 10 |
| per sample: the MAC and its operands | 3 |
| per sample: call/rts into `_mrf_rns28` | 15.04 |
| per sample: `_mrf_rns28`'s body and the store | 12 |
| **per sample** | **67.1** |
| × 16 samples | 1,073 |
| the control-rate section, once a block | 26 |
| the chain's own call/rts | 15.04 |
| **per node, per block** | **≈ 1,130** |

Twelve nodes is **13,560 cycles a block**. At 983.04 MHz and 3,000 blocks/s
the budget is 327,680 cycles a block, so one point of budget is 3,277
cycles: **the twelve switched-off aux inputs are costing chip 2 about 4.1
points of budget to do nothing.**

The same model over S29's sixteen scoped nodes predicts 2.91 points where
S29 measured 3.53, so it is a floor and the prediction is quoted as a band:
**−4.1 to −4.9 points on chip 2, and 0.00 on chip 1**, which has no node of
this class and is therefore this session's built-in control.

### 1.2 The cheapest test — per node, not per run

The scope gate one level up gates whole RUNS because a scope class is ONE
word for the whole chain. `on` is not: it is twelve independent cells the
host writes, and the twelve are not off together by construction — a run
gate would need an aggregate word that nothing in the firmware maintains.
So the gate is **per node**, and it is two words:

```
    r2 = dm(_auxin_on_C2_SNK_IN_01);      /* the cell the host writes */
    r2 = pass r2;
    if ne jump (pc, .c2brunabC2_SNK_IN_01_run);
    r2 = dm(_auxin_byp_C2_SNK_IN_01);     /* is the block already silent? */
    r2 = pass r2;
    if ne jump (pc, .c2brunabC2_SNK_IN_01_end);
.c2brunabC2_SNK_IN_01_run:
```

Six instructions, one of them a taken branch: **11 cycles against 1,130**.

### 1.3 The second word, and the block the node stops being called on

**The gate cannot be `on` alone, and that is the whole design.**
`_blk_<nid>` is read every sample by `C2_MIX_MAIN_L` and `_R`; a node that
simply stops being called leaves its last block sitting there, and the mix
bus goes on summing it for ever — the switched-off snake return would
repeat 16 samples of whatever it last carried, at 3,000 blocks a second.

So the bypass is **two mechanisms, one block apart**:

1. **The park** (S23 gate 2's mechanism, applied to this class): when the
   node IS called with `on = 0`, it publishes a block of zeros and returns
   before the wrapper, then sets `_auxin_byp_ = 1`.
2. **The chain gate**: skip the call only when `on` is 0 **and**
   `_auxin_byp_` says the block downstream reads is already that silence.

A 1 → 0 flip therefore costs one more call — the block that zeroes the
buffer — and the calls stop from the next block on. A 0 → 1 flip takes
effect **on its own block**: the gate's first test is the host's own cell,
so there is no config word, no commit and no latency in the path.

### 1.4 What AUX_INPUT holds, and why this class can be skipped at all

The node's entire state is `on`, `level`, `level_target`, `level_step`,
`level_frames`, `q`, its scalar `_buf_` and its block. **There is no delay
line, no filter state and no accumulator** — which is exactly why this class
is safe to skip and why a `DELAY`, a `COMPRESSOR` or an `FX_ENGINE` reverb
tail would not be. Nothing goes stale except the level ramp, which does not
advance while the node is not called.

That is dealt with on the way back in. A level written DURING the off period
leaves a pending ramp that would otherwise play out from where it stopped,
minutes later; on resume the node clears `_auxin_level_frames_`, which sends
the existing code down its `.no_auxramp` path and makes the level the
target — **which is where the ungated build's ramp had long since arrived**.

**The one behavioural difference, stated rather than buried**: if the host
writes a new level and flips `on` within a ramp length of each other (3 ms
up, 8 ms down on `GainFast`), the bypassed build arrives at the target
immediately where the control would still be ramping. `on` is an
`InstantCtl` cell in **both** builds — the step at the flip is the cell's,
not the bypass's — and it dominates either way.

### 1.5 What it costs to carry

`DSP4_AUXIN_BYPASS` defaults to 0 and **emits not one byte** at that
default: the control build below reproduces the window candidate's md5s
exactly. With it on, chip 2's boot stream grows 1,392 bytes (407,584 →
408,976) and **chip 1's image is unchanged, byte for byte**.

## 2. Gate 2 — built and staged as `s32` only

### 2.1 The change is in the GENERATOR, and the flag-off build proves it

Four files in `tools/dsp/dsp_codegen.py` and one flag in `build.sh`; the
generated tree is regenerated, never edited:

* `_C2_PARK_GATE` gains `AUX_INPUT`, with a guard (`_C2_PARK_GUARD`) and a
  flag word (`_C2_PARK_FLAG`) — FX_ENGINE's park is unguarded and shipping,
  this one is a proposal and is not;
* `blk_wrap_body` takes `park_guard` / `park_flag`, so the park is wrapped in
  `#if DSP4_AUXIN_BYPASS` and publishes `_auxin_byp_<nid> = 1` with the
  silence;
* `gen_aux_input_fixed` declares `_auxin_byp_<nid>` and clears it — with the
  ramp's frame count — at the top of the control-rate section;
* `emit_chain` emits the six-instruction gate and its externs, in all three
  orderings, under `#if DSP4_BLOCK_KERNELS && DSP4_AUXIN_BYPASS`;
* `gen_block_header` carries the flag's default (0) into `dsp_block.h`.

**Twelve node files, `chip2/process_chain.asm` and `dsp_block.h` regenerate;
`chip1/process_chain.asm` does not, because chip 1 has no node of this
class.**

## 3. Gate 3 — driven at worst use: WHAT WAS TAKEN, AND WHAT WAS NOT

### 3.1 The driven regime was NOT available this session, and why

**The dispatch's own bench rules and its gate 3 do not compose today, and the
rule wins.** The driven capacity ladder needs the `driveall` LOGIC bitstream
— that is what broadcasts the CM4's playback onto every DSPA input lane so
the graph can be measured under load for zero DSP cycles (S19) — and this
session was told, in as many words, **"do not reflash the CPLD"**, because
the analog board may be attached and the 74HC595 chain is never to be
approached. A CPLD reconfiguration tri-states the lanes that chain sits on
for the length of an SVF, which is exactly the hazard that rule exists for.

So the CPLD was not touched. `./loadlogic.sh --id` returned no reply, which
is what the SHIPPING bitstream gives (it has no capture path), i.e. the bench
is as S31 left it.

**What that costs, precisely, and what it does not.** With the shipping
bitstream the CM4's playback reaches ONE lane's two slots, so the rows below
carry the regime the log records:

```
  DRIVEN REGIME: 0 of 64 dynamics envelopes live on chip 1
  DRIVEN REGIME: 27 of 32 dynamics envelopes live on chip 2
```

Rows A and B are **not affected at all** — they are taken with the stimulus
STOPPED, by the same script, in the same order, and are directly comparable
to S29's rows A and B on the same image. Rows C and the USE rungs are taken
with a partial regime and are **labelled as such throughout**; they are not
the fully driven rows S27/S28/S29 quote.

**And row B is the row that overruns.** S29's control read
100.78 % / 100.87 % on chip 2 with **1,912 missed blocks** at
silence with the load applied — 0.03 points from the fully driven worst-use
row it also measured (100.81 %). The question this session was sent to
answer does not need the stimulus: S29 measured the class cost across six
regimes and it varied by 0.26 points, because a per-CALL gate does not care
what the signal is doing.

## 4. Gate 4 — the flip, on the part

`tools/pi/dsp4_s32_flip.py` flips the cell the host writes and reads the
node's own state and its published block back out of the part:
`_auxin_on_`, `_auxin_byp_`, `_auxin_q_`, `_blk_<nid>` and the block of the
node feeding it. Four snake returns and the Pi playback input, on the s32
image, with the CM4 playing.

### 4.1 `C2_PI_IN` — the audio witness, at full scale

The Pi playback path is live end to end under the standing overlay (S29
proved it stage by stage), and it feeds an AUX_INPUT of exactly the class
under test. The stimulus is the ±0.9999 square the driven ladder uses:

| | `_auxin_on_` | `_auxin_byp_` | `_auxin_q_` | `_blk_C2_PI_IN` | `_blk_C2_XR_PI_L` (its input) |
|---|--:|--:|--:|---|---|
| off (as booted) | 0 | **1** | `0x00000000` | **all zero** | `0xf0000000 0xf0000000 0x0fffffff …` |
| **on** | 1 | **0** | `0x10000000` | `0x0fffffff 0xf0000000 0x0fffffff …` | `0x0fffffff 0xf0000000 0xf0000000 …` |
| off again | 0 | **1** | `0x10000000` | **all zero** | `0x0fffffff 0x0fffffff 0xf0000000 …` |

**A node the chain had not called for minutes passes full-scale audio at
unity the moment its cell goes to 1, and publishes exact silence the moment
it goes back to 0.** The output alphabet is the input's, sample for sample,
which is what unity gain through this node looks like; there is no partial
block, no ramp-in and no gap.

### 4.2 The four snake returns — the state witness, and a signal after all

`C2_SNK_IN_01..04`, flipped 0 → 1 → 0 one at a time. The snake lane on a
rev C D24 is not driven by a stage box, but it is not dead either: it reads
`0xffffffff` — minus one LSB of Q4.28 — and that is enough to show the
transfer, because the node passes it through at unity and zeroes it when
off:

| | `_auxin_byp_` | `_blk_C2_SNK_IN_0n` |
|---|--:|---|
| off | 1 | all zero |
| on | 0 | `0xffffffff` × 16 — its input, at unity |
| off again | 1 | all zero |

All four behave identically, and so does the gate: `byp` set while off,
cleared on the block the node runs again.

### 4.3 What FAILED, and why it is inert — `_auxin_q_` is left stale

**One check of the six fails on every node and the tool reports it rather
than rounding it off**: after the node goes back off, `_auxin_q_` still
holds `0x10000000` instead of returning to 0.

The mechanism is the park itself. On the 1 → 0 block the chain calls the
node, the park sees `on = 0`, publishes the silence and **returns before the
body runs** — so the control-rate section that recomputes `q` never runs
again, and the last value stands.

**It cannot reach the audio**, and the reason is the order inside the body:
the sample path runs only on blocks where the node is CALLED and not parked,
i.e. only when `on` is non-zero, and sample 0 of every such block recomputes
`q` from `level` and `on` *before* the first MAC. A stale `q` is therefore
never the coefficient of anything. The published block is zero either way —
measured above, all sixteen words, on five nodes.

**The fix is one instruction in the park path** (`dm(_auxin_q_<nid>) = r0`
beside the store that sets the flag, `blk_wrap_body`), and it is NOT MADE
HERE: it would change the image this session measured, for a word that no
kernel and no cell reads. It is filed as S32-3 for whoever takes the lever
into a shipping configuration.

## 5. What this puts to PW

### 5.1 The number

**With the twelve switched-off aux inputs bypassed, D32 chip 2 reads 95.64 %
of budget with ZERO missed blocks on the row that misses 1,898, and 95.69 %
on the worst-use rung that misses 1,900 — against 100.86 % and 100.85 % on
the same night, the same instrument and the same bitstream. The twelfth aux
fits, by 4.3 points.**

The saving is **4.84 to 5.22 points of chip 2**, flat across every regime
measured (silent, loaded, stimulus on, crosspoints closed, crosspoints
open), which is what a per-CALL gate looks like: the nodes are skipped or
they are not, and nothing about the signal changes the price. **Chip 1 does
not move**, and cannot: it has no node of this class and runs the same bytes.

It is larger than the 3.43–3.69 points S29 priced the whole scope class at,
and that is not a contradiction — S29 gated 16 nodes of which 8 were these,
and this arm reaches **twelve**: the eight snake returns plus the codec, Pi,
USB and BT feeds, none of which is scoped to a product and all of which are
off in every capacity row.

### 5.2 What PW is being asked

**This is a lever, not a product change.** Nothing about the D32R snake, its
cells, its lane or its contract moves: `Snk[1-8]On/Level` are written and
read exactly as before, and a snake return that is switched ON costs exactly
what it costs today (§4 measured it passing audio at unity). What changes is
that a switched-OFF aux input stops being called.

Three things go with that:

1. **It changes the shipping image.** `shipping.config.s26` does not carry
   `DSP4_AUXIN_BYPASS`; the arm is a pair of its own (`s32_*`) and the
   candidate is untouched. Taking it into the window is PW's call, and it
   needs the audio bar the window candidate carries (famverify / the numeric
   arms), which this session did not re-run.
2. **One stale word is on the record** (§4.3, S32-3) with its one-instruction
   fix named. It is inert today; it should not be inert and undocumented in
   a shipping image.
3. **The deficit it closes is 0.81 points and it returns 4.9.** Even at the
   most conservative reading — the eight snake nodes alone, which S29's
   apportionment puts at about two thirds of it — it closes the gap with
   room over.

# S48 — first audio on rev C: the DSP side is proved live, the loop is correlated, the stimulus is what is missing

**THE D24 HAS A LIVE AUX 1 OUTPUT ON REV C FOR THE FIRST TIME.** `C2_AUX_OUT_01`
— DAC_08, analog J45, rear XLR OUT_01 — carries **|peak| 0.00423 Q4.28 =
−65.5 dBFS, 8 of 8 words non-zero, inside the ±1.0 Q4.28 criterion**, fed by
MIC 5 → strip 5 → AUX 1 at unity with every other strip muted and off both
buses. S39-6 read that lane at 1.538 Q4.28 (+3.75 dBFS, above full scale);
S46 read it at exactly 0.00000 on an unpowered converter bank and said
honestly that the lane *"will only be proved live when the converters are"*.
They now are, and it is. **What is NOT proved is a level through the analog
loop**: with PW's cable from OUT_01 back into MIC 5, opening AUX 1 moves MIC
5's RX lane by **+0.36 dB** against a control lane's +0.05 dB — repeatable,
directional, seven times the control, and **under S40 gate 3's 1 dB bar**,
because the only thing on the bus is the strip's own converter noise. The
image offers no host-settable stimulus that reaches the node chain (§6). No
+5 V rail figure appears in this document because no level was taken that
needed one.

---

## 1. The link was dead, and the cause was CS_M

The session opened against a dead parameter link. The S42 pair booted exactly
as in S46 — md5s re-verified on the unit, `825f9b7dac5978c973550c8e40819ba9`
and `7b1311e8e56f008fa98046cab59293c6`, **451,584 B on CS1 in 605.7 ms**,
**308,224 B on CS2 in 413.4 ms**, S46's timings to a tenth of a millisecond —
and then `cannot phase the parameter link: MAGIC never came back`, on both
chips, twice.

Reading the raw words rather than trusting the exception: 400 collects
returned **4 distinct word-pairs, 0 hits on MAGIC**, 390 of them the
transmitted word **right-shifted by exactly one byte**. Four checks:

| question | test | answer |
|---|---|---|
| a slipped answer? | search the reply for MAGIC at **every bit offset** | not there, 6 tries/chip — **no answer at all** |
| an MCU bit-banging? | delay at 8 MHz and 10 MHz | **exactly 8 bits at both** — synchronous logic |
| MISO floating? | force GPIO9 `a0 pd`, then `a0 pu` | **unchanged** — MISO is driven |
| is it the SHARC? | A/B, chip select asserted vs deasserted | **byte-identical** — the SHARC drives nothing |

**The hub named it: GPIO27 was idling as an input with a pull-DOWN, holding
CS_M LOW, which leaves the analog MISO buffer U2 ENABLED and driving SPI2
MISO continuously.** H1S1 stopped holding CS_M high when it was reflashed on
09-14. Setting GPIO27 to input pull-UP (CS_M high, U2 tri-stated) fixed it
outright — the next probe returned `w0 0xE0002000 / w1 0xD5B40001`, echo and
MAGIC, word-aligned, and the same A/B now reads the SHARC with CS asserted
and silence with it deasserted.

**Two things this session got wrong before the hub's answer, recorded as
corrections rather than quietly dropped.** The echo was attributed to the
74HC595 chain's own shift output — wrong device, right bus. And the silence
was hypothesised to be the over-budget graph starving the link once the
converters clocked — **also wrong**: the graph *is* over budget
(`BLK_OVERRUN` 2,245 / 2,230 accumulated at boot) and the link answers
perfectly regardless. AN_EN was read at every gate and written at none
throughout, so neither error cost the bench anything.

by construction.

## 3. A defect that had to be fixed to run this session at all

`dsp4_apply_strip.py` line 33 is `sys.argv = ['s']` — emptying argv so
`dsp4_scope`'s import-time parser does not consume the arguments — and
`STRIP`/`AUX` were read **after** it. Both were therefore pinned to 1 on every
invocation ever made. Asked for strip 5, the tool printed `strip 5 -> MAIN and
AUX 1` and then wrote and read back `Chan001…` cells, reporting 13 ok. That
is a wrong answer dressed as a right one.

Fixed by taking `sys.argv[1:]` **before** the clear, exactly as
`dsp4_s42_align.py` already does (`_argv = list(sys.argv)`). Nothing in the
prior record is invalidated — S46 §4 ran `1 1` and correctly reported strip 1
— but any "strip N" claim predating this fix is strip 1 wearing another
number.

## 4. Gate 2 — MFD PASS, RX right on every populated lane, AUX 1 live

**MFD: PASS.** Every lane's `SPORT_MCTL.MFD` equals the generated table on
both chips — chip 1 rx `[2,2,2,2,2,2,1,2]`, chip 1 ic `[1,1,1]`, chip 2 ic
`[1,1,1]`, chip 2 tx `[2,2,2,1,2]`. Nineteen lanes, nineteen matches,
including the deliberate CPLD/fabric exceptions.

**RX, chip 1's twelve converter lanes.** **Bits 6:0 are never set on any
lane** — the 24-in-32 pad is where it should be — and bit 31 is exercised on
every lane (13–20 words of 32):

| lane | dBFS | | lane | dBFS |
|---:|---:|---|---:|---:|
| 1 | **−113.9** | | 7 | −72.3 |
| 2 | **−117.6** | | 8 | −81.7 |
| 3 | **−116.1** | | 9 | −67.6 |
| 4 | **−118.4** | | 10 | −81.5 |
| 5 | −69.9 | | 11 | −76.8 |
| 6 | −75.0 | | 12 | −81.5 |

**Lanes 5–12 are all inside the −65…−85 dBFS converter band, with eight
distinct noise floors** — the §5.1 criterion, met on every lane that has a
populated analog section behind it. **Lanes 1–4 are the MIC 1–4 section the
bench state records as DEAD**, and −114…−118 dBFS is what an unpopulated
front end reads. The tool scores them `**BAD**` and fails the whole RX
verdict on them, because its band test has no notion of a depopulated
section — it wants the same kind of guard S46 gave it for an undriven bus.
**That FAIL is the instrument, not the part.**

**Chip 2's inter-chip receive** resolves by name: `C2_RECV_MAIN_L` and
`C2_RECV_AUX_01` carry **16 distinct values** with bit 31 exercised; the
other five lanes read 1 distinct value. Those two are exactly the lanes
strip 5 feeds.

**TX: PASS.**

| node | |peak| Q4.28 | dBFS | non-zero | destination |
|---|---:|---:|---:|---|
| **`C2_AUX_OUT_01`** | **0.00423** | **−65.5** | **8/8** | DAC_08 → J45 → **rear XLR OUT_01** |
| `C2_AUX_OUT_02` | 0.00000 | −inf | 0/8 | DAC_07 → Aux Out A2 (unrouted) |
| `C2_MAIN_OUT_01` | 0.00651 | −61.8 | 8/8 | DAC_12 → J56 MAIN L |
| `C2_MAIN_OUT_02` | 0.00751 | −60.5 | 8/8 | DAC_11 → J57 MAIN R |
| `C2_MAIN_ST_OUT` | 0.00628 | −62.1 | 8/8 | B_O3, no D24 sink |

This proves what the DSP handed the AK4458, not what the AK4458 latched.

## 5. Gate 3 — the loop is correlated, and honestly not yet proved

PW's patch is rear XLR OUT_01 (AUX 1, J45) into MIC 5's rear XLR (J25), so the
stimulus must come from the DSP side. The question was asked the way S39-9
recommends — with a **control**, which is stronger than a tone because it has
a negative arm — by toggling `Aux001Mute001` and watching MIC 5's RX lane,
with a second lane the loop does not feed as a witness:

| arm | AUX 1 | MIC 5 RX | control lane 9 |
|---:|---|---:|---:|
| 0 | open | **−68.19** | −66.84 |
| 1 | MUTED | −68.55 | −66.69 |
| 2 | open | **−68.17** | −66.89 |
| 3 | MUTED | −68.62 | −67.18 |
| 4 | open | **−68.32** | −66.92 |
| | | **Δ +0.36 dB** | **Δ +0.05 dB** |

The open and muted arms **do not overlap**, the arms alternate so a one-way
drift cannot fake it, and the looped lane moves **seven times** the control.
The loop is carrying something. But **+0.36 dB is under S40 gate 3's 1 dB
bar**: AUX 1 leaves at −65.5 dBFS carrying only the strip's own converter
noise, and comes back about 7 dB beneath MIC 5's own floor. The correct
statement is **"the stimulus is below the noise"**, not "the loop is open".

`Aux001Mute001` was restored to its entry value (0) by the tool, including on
the exception path.

## 6. Why there is no bigger stimulus, and the wrong finding it nearly caused

`scope.asm` offers impulse (mode 1) and step (mode 2) only; `C1_NOISE` has no
oscillator and no consumer (S39-9). Driving `_buf_C1_IN_05` with a 0.25 Q4.28
step and capturing that same address returns **`04000000` for all 1,024
samples** — the injector works exactly as documented. Yet the AUX 1 and MAIN
TX lanes **never rose above their noise** while it ran.

The naive reading of that pair of facts is *"the step dies inside strip 5"* —
which is precisely the S38-5 / bench-recipe-17 defect signature, and would
have been filed as one. **It is not that.** `scope.asm`'s own comment settles
it: under `DSP4_BLOCK_KERNELS` **both** injectors run in every block; the
per-sample `_scope_inject` is what `_scope_record` captures, while
`_scope_inject_blk` *"rewrites the whole block and is the write the chain
actually reads"* — and that one is gated behind the build-time
`DSP4_SCOPE_BLK_TAP`, with **no memory POKE on the diag link, only PEEK**, so
the host cannot reach it on this image at all.

**On the shipping D24 image there is no host-settable stimulus that reaches
the node chain.** A level-grade first audio needs one of:

1. **an external source into MIC 5** — which is what the loop patch displaced,
   so it is loop *or* tone, not both, until a second input is used;
2. **a `DSP4_SCOPE_BLK_TAP` build** of the pair, which makes the block
   injector host-reachable and turns this into a ten-minute measurement;
3. **the MIC 1 → AUX 1 loop of S46 §6 item 5** on a second channel, leaving
   MIC 5 free for PW's source — blocked today because MIC 1–4 is the dead
   section.

Option 2 is a hub call and a rebuild, not a bench tweak, which is why this
session stops here rather than reaching for it.

## 7. Gate 4 — not taken

None of the preliminary set was attempted: the gain sweep on the 595 codes,
mute depth, polarity, the three-point frequency sweep, terminated noise floor,
or THD at −20 dBFS. Every one of them is a **level** measurement, and gate 3
has not produced a level to measure — taking them on a −68 dBFS noise floor
would produce numbers with no signal in them. `app cli chain-set` was
therefore never called and the mic gain codes were never moved; the chain
stayed at the hub's safe image throughout. Per PW's standing convention no
dBFS figure is quoted here without the +5 V rail beside it, and since no
signal-bearing level was taken, none is.

## 9. What changed in the repo

* `tools/pi/dsp4_apply_strip.py` — the argv fix of §3. Behaviour is otherwise
  byte-for-byte what it was.
* `tools/pi/dsp4_s48_loop.py` — **new**. The AUX-1-mute loop test with an
  alternating-arm schedule, a control lane, restoration of `Aux001Mute001` on
  every exit path, and a refusal to measure when `_rx_active_buf` peeks 0
  twice (see below).
* `tools/pi/dsp4_s48_stim.py` — **new**. Drives a strip input from
  `scope.asm` and reports the TX lanes and the looped RX lane around it.
  Clears the injector on every exit path.

Both new tools take the symbol directory as an argument, defaulting to the
staged pair, because **`/home/app/dspboot/chip1.sym.json` is not this image's
map** (`b694276e…` against the staged `f2e0c082…`). A first cut of the loop
tool hardcoded the dspboot path and every lane read `-inf` across all five
arms — a clean, symmetrical, entirely fictional "the converters are silent",
because `_rx_active_buf` peeked as 0 and every window read landed at absolute
address 128. `dsp4_apply_strip.py` survives the same hardcoding only because
it deliberately uses no `peek()` at all.

No contract artefact moved: `defs.lock`, `dsp.csv`, the SPI addresses, every
`_matrix.csv` and every generated file are untouched, so there is no version
bump.

# COMP family — hardware vs fixed_ref, 2026-08-23

provenance: AI-drafted 2026-08-23 — prose may carry a statistical watermark; rewrite by hand before publication, then remove this header.

**PASS — 0 LSB at all 7 input levels**, and the gain computer matches
`fixed_ref.comp_gain` bit for bit when fed the measured envelope.

**One real defect found and fixed**: `parallel = 1.0` overflowed to −1 and
silently bypassed the compressor. See below — it is the substantive result.

GATE and LIM are NOT covered here. This report is COMP only.

## Method

Step stimulus injected at `_rx_slot_C1_IN_01` and captured at
`_buf_C1_COMP_01` with the DSP-side scope. A step is the right shape here:
its settled tail gives the static gain reduction and its leading edge gives
the attack envelope, from one capture.

Chain is `IN -> GAIN -> FILT -> EQ -> GATE -> COMP`. GAIN, both FILT
sections and all four EQ bands are forced to unity and the GATE is switched
off at the start of every run, so what reaches the compressor is exactly the
injected step.

**Worst error 0 LSB (Q4.28).** Below threshold the output is the input
exactly, as it must be.

The model is the full chain, not just the gain law: envelope by
`fixed_ref.envelope_step`, gain by `fixed_ref.comp_gain`, then
`wet = rns28(rns28(dry*gain)*mkq)` and `out = dry + rns(parq*(wet-dry), 31)`,
with every parameter conversion modelled in float32 as the DSP performs it.

Isolating the gain computer: with the **measured** settled envelope
134,217,726 the hardware returns gain 80,280,541 and `fixed_ref.comp_gain`
returns 80,280,541 — **0 LSB**.

## A trap worth recording

A first pass showed a 183 LSB error and it was **my model, not the DSP**. I
assumed the envelope settles to `|x|`; in fixed point a one-pole sticks
short, because once `rns(alpha*(target-env), 31)` rounds to zero the
envelope stops moving. Here it settled at 134,217,726 against a target of
134,217,728 — two LSB low, which is enough to move the gain. Running the
envelope model forward instead of assuming its limit closed the gap to zero.

Also: `attack` and `release` are **per-sample alpha coefficients, not
seconds**. `attack = 0.001` is a ~21 ms time constant, not 1 ms. That cost
a wasted measurement whose 600-sample window never settled.

## The parallel defect

`_comp_parallel` converts as `par * 2^31` into Q0.31. At `par = 1.0` that is
exactly 2^31, which int32 cannot hold: `fix` wrapped and stored **−1**,
which in Q0.31 is −4.7e−10 — numerically zero. The blend is
`out = dry + par*(wet - dry)`, so the **maximum** parallel setting produced
the **dry** signal: identical output to `par = 0`, with a perfectly working
compressor sitting behind it.

Measured on a −6.02 dBFS step, threshold −20, ratio 4:

| parallel | settled output | meaning |
|---|---|---|
| 0.0 | 134217728 | dry (by design) |
| 0.5 | 87179000 | half wet |
| 0.999 | 40234347 | −16.49 dBFS, 10.5 dB GR |
| 1.0 **before fix** | 134217728 | dry — the bug |
| 1.0 **after fix** | 40140271 | full wet, matches model exactly |

Fixed in the generator (`tools/dsp/dsp_codegen.py`) by clamping the
converted value to `0x7FFFFFFF`, then regenerating all 43 COMP nodes. Both
`par = 0.999` and the clamped `par = 1.0` are now bit-exact against the
model.

D24 is unaffected: its SHARC tree still carries the float compressor, which
has no fixed-point conversion to overflow.

## Open — for the hub

`_comp_parallel` **defaults to 0.0**, and at 0.0 the node emits the dry
signal. So a compressor with a sensible threshold and ratio does nothing at
all until the host writes `parallel`. That may be intended — the host may
always write it — but the default state of the node is "bypassed" while
`CompOn` reads 1, which is a trap for anyone bringing up a strip by hand. It
cost real time here. Worth either changing the default or documenting it
loudly. Same semantic exists in D24's float node.

# EQ / FILT family — hardware vs fixed_ref, 2026-08-23

provenance: AI-drafted 2026-08-23 — prose may carry a statistical watermark; rewrite by hand before publication, then remove this header.

**PASS — 0 LSB on all 13 coefficient vectors**, once the DSP's own float32
coefficient conversion is modelled. Magnitude response matches the analytic
RBJ filter to **0.0000 dB** at every frequency checked, against a ±0.01 dB
tolerance.

**This family found a real bug that had shipped through every biquad in the
product.** See "The b1 defect" below — it is the substantive result here;
the pass table is what it looks like afterwards.

## Method

Stimulus and capture are both inside the DSP (`src/scope.asm`, added for
this family). An impulse is injected into `_rx_slot_C1_IN_01` immediately
after `_scatter_chip1` — the one point in the sample loop where an input
holds a value the node chain has not yet consumed — and the node output is
recorded every sample into a 1024-word buffer the host reads back over the
parameter link.

The Pi audio path is NOT used and could not have been: measured the same
day, a counter played through it returns with ~8x gain and reordered by up
to ~190 samples. A swept sine through that channel would have measured the
channel.

An impulse response characterises a biquad completely, so this is checked
**bit-exactly** against `tools/dsp/fixed_ref.py::biquad` rather than to a dB
tolerance. Chain: `_rx_slot_C1_IN_01 -> GAIN_01 -> FILT_01 -> EQ_01`. GAIN
and both FILT sections are reset to unity at the start of every run.

measurement rather than assumed: the `both` vector scores 0 LSB in that
order and 2 LSB reversed. Two biquads in series commute mathematically but
not bit-exactly, because each rounds its own output.

## The b1 defect

`_bq_fx_convert_N` held `b1` in `f1` across the `b0` conversion and then did
`r1 = fix f5` to store `b0q`. On SHARC the register file is unified: **`r1`
IS `f1`**. `b1` was destroyed before `n1 = b1 + 2*b0` ever read it.

It did not fail loudly. `b0q = 0x10000000` reinterpreted as a float is
2.6e-29, which adds as zero, so `n1` came out as exactly `2*b0` and every
biquad in the product ran with **b1 = 0** — EQ and HPF/LPF alike. `b2`,
`a1` and `a2` live in `f2`/`f3`/`f4` and were never touched, which is why
unity coefficients looked perfect and only one term was wrong.

Before the fix: worst 53,687,091 LSB, 3 of 9 EQ vectors failing. After:
the table above. The fix puts the conversion result in `r9`, clear of
`f0`–`f8`.

Two things made it findable. `b1 = +1` and `b1 = −1` produced the
**identical** impulse response, which no correct implementation can do; and
the `mixed` vector was wrong by precisely `(b1 + 2b0 − 2b0) * x1`, which
names the missing term outright.

## Open — for the hub, not silently accepted

`_bq_fx_convert_N` converts in **float32**, whose 24-bit mantissa cannot
represent Q4.28 exactly, while `fixed_ref.biquad_coeffs_q` uses float64.
Coefficients therefore land 1–3 LSB off the normative value, worth up to
22 LSB in the response here. D5 says one numeric spec across targets, so
this needs a decision:

- send **pre-quantised Q4.28 coefficients** over the wire, letting the host
  do the exact conversion it already implements (changes the wire
  contract); or
- amend `shared/numeric-spec.md` with a stated coefficient-conversion
  tolerance.

The kernel itself is not in question: `_bq_fx_cascade_N` matches
`fixed_ref.biquad` bit for bit on all 13 vectors.

## Also worth keeping

The EQ measured wrong for a while because `C1_FILT_01` still held the
previous sweep's `lpf b0 = 0.1` and the EQ sits downstream of it. A test
that inherits chain state measures the wrong thing convincingly. Every run
now resets GAIN and both FILT sections before it measures.

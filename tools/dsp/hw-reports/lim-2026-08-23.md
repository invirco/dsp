# LIM family — hardware vs fixed_ref, 2026-08-23

provenance: AI-drafted 2026-08-23 — prose may carry a statistical watermark; rewrite by hand before publication, then remove this header.

**PASS — 0 LSB at all 6 input levels.** No defects found. The limit lands
at exactly **−0.500 dBFS** against a −0.5 dB threshold.

## Method

`C2_AUX_LIM_01`, on chip 2. Step injected at
`_rx_ic_slot_C2_RECV_AUX_01` and captured at `_buf_C2_AUX_LIM_01` with the
DSP-side scope, using the node's default parameters (threshold −0.5 dB,
attack alpha 0.5, release 0.001).

Four nodes sit between the injection point and the limiter —
`RECV_AUX → AUX_FDR → AUX_EQ → AUX_GEQ → AUX_AFB → AUX_LIM`. Rather than
force four more nodes to unity and hope, **the limiter's own input was
captured too** (`_buf_C2_AUX_AFB_01`) and the model was driven from that.
The measurement therefore does not depend on any assumption about the
chain ahead of it. As it happened the chain was transparent, but that was
confirmed rather than assumed.

The limiter is a brick-wall compressor: the node hard-codes
`slope = 0x7FFFFFFF` (ratio ∞) with no knee, no makeup and no parallel
blend — `out = rns28(dry × gain)`.

`fixed_ref.envelope_step` → `fixed_ref.comp_gain` → `rns28` multiply, with
the float32 parameter conversions modelled as the DSP performs them.

## Two bench faults this family exposed

Neither was in the limiter; both returned plausible wrong answers rather
than errors, and both are fixed in `dffca40`.

**Chip 2 was running chip 1's firmware.** `dsp4_boot.py --dir .` left it
that way — a hazard already recorded in `tasks.md`. Combined with `Scope()`
never passing `rdy_gpio`, a `Scope(2)` answered as chip 1 while being read
with chip 2's symbol addresses, and an entire chip-2 chain walk read as
dead. `Scope.check_chip()` now refuses to measure unless `DIAG_CHIP_ID`
matches the requested chip. **Read CHIP_ID before believing any chip-2
measurement.**

**The per-sample SPI poll was too expensive for chip 2.** It fixed chip 1's
link (8/25 → 25/25 raw reads) and broke chip 2: after `CONFIG_COMMIT` it
stopped restamping `_diag_boot_stage`, `BOOT_STAGE` read 0 and the link
went intermittent — a main loop no longer finishing its block. Now polling
every 8 samples (6000/s), and both chips run clean at 20/20.

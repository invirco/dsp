# D24 output patch — which DSP TDM slot reaches which connector

**A DEFS CANDIDATE.** It is proposed for `defs`, not landed by this repo. The
rows below are traced, not assumed, and the DSP side has been changed to match
them for the two signals S40 needs (§4); the rest of §5 is a list of product
decisions that only PW can make.

Filed by S42 (dsp), 2026-09-13. Sources, all of them primary:

| what | source |
|---|---|

| TDM slot → converter channel | the AK4458's own straps: `SDTI1` only, `TDM0-1 = 01`, `DIF0-1 = 10` ⇒ channel *n* is slot *n* (D24 Analog rev B sheet 13/64 "ADC8" and the DAC8 sheets) |

| connector → rear-panel name | `defs/products/d24/d24-io.csv`, and sheet 12/64's own block names |

## 1. The two facts that make this table necessary

**The OUT_1-8 block is REVERSED.** AK4458 U81 channel *n* comes out of rear
XLR `OUT_(9−n)` — traced independently on the analog board and again on the
phone-jack board, all eight channels, same refdes stride (mx26
`d24-analog-paths.md` §1). mx26 filed that in S-11 with the question "either
the dsp slot map compensates already, or the sixteen `OUT_nn` rows need their
`carries` column changed". **This session is that check, and the answer was:
it did not compensate.**

**The OUT_9-16 block is not reversed — it is a different derangement**, and it
is only readable from sheet 12/64, which draws the DAC's 16-wire bus into six
named blocks:

```
PHONES_L  <- DAC[0..1]      MAIN_R <- DAC[4..5]      MON LR <- DAC[12..15]
PHONES_R  <- DAC[2..3]      MAIN_L <- DAC[6..7]      SUB_W  <- DAC[10..11]
                            (DAC[8..9] = channel 5: drawn dangling, no sink)
```

`DAC[2n]`/`DAC[2n+1]` is channel *n+1*'s N/P pair, which the netlist confirms
pin for pin (`OUT_9-16_DAC0` = U92.19 = `DA_CH1_N`).

## 3. The row S39-5b corresponds to

S39-5b reported "only ONE of the eight chip-2 TX lanes is ever non-zero" and
"the main outputs are not reaching the TX buffer at all". **Both halves are an
instrument artefact, of exactly the class S39-1 found in the symbol map.**

`tools/pi/dsp4_s39_outpath.py` walks `_c2_tx_off[lane]` for `lane in
range(0, 8)` and labels the result "TX lane 0..7". That array is not indexed by
TDM lane. It is the **24-entry TX NODE table**, ordered by (sport, slot), and
its first eight entries are the eight nodes on lane B_O0. So:

* the "eight lanes" were `C2_AUX_OUT_01..08` — under the OLD patch, aux 1..8;
* "lane 0 is AUX 1 and follows `Aux001Mute001`" is correct and is entry 0;
* "lanes 1–7 always zero" is **aux 2..8 carrying nothing, which is correct
  behaviour** — nothing was routed to them;
* **MAIN was never in the window the tool read.** `C2_MAIN_OUT_01..04` were
  entries 12–15 and `C2_MAIN_ST_OUT` entry 18. The tool stopped at 7.

So there is no "seven silent lanes" defect, and no "MAIN absent at the TX
buffer" defect. **What there was instead is worse and is fixed in §4:** MAIN
was being written to TDM slots that reach a dead DAC channel and the monitor
jacks, and AUX 1 was being written to the slot that reaches the **Aux Out A8**
XLR.

Under the S42 patch, the equivalent of that eight-row window now reads
`C2_AUX_OUT_08, 07, 06, 05, 04, 03, 02, 01` — the same eight nodes in the
reverse order. `tools/pi/dsp4_s42_align.py` resolves nodes by NAME through
`_c2_tx_ptrs` instead of by position, so it cannot make this mistake again.

## 4. What the DSP side was changed to match (landed in this repo, S42-2)

Two output-patch tables in `tools/dsp/gen_dsp_csv.py`, `AUX_DAC` and
`MAIN_OUT_DAC`. Twelve nodes moved slot; **no SPI address moved and no node
was added or removed** — `dsp.csv` differs in 12 rows and the allocator's
totals are unchanged (chip 1 page 1/addr 4967, chip 2 page 1/addr 2175).

| node | was | is | why |
|---|---|---|---|
| `C2_AUX_OUT_01..08` | `DAC_01..08` | `DAC_08..01` | the OUT_1-8 reversal; aux *n* now reaches the XLR marked **Aux Out A*n*** |
| `C2_MAIN_OUT_01` | `DAC_13` (**no connection**) | `DAC_12` | analog J56 = **MAIN L** |
| `C2_MAIN_OUT_02` | `DAC_14` (the Centre/LF XLR) | `DAC_11` | analog J57 = **MAIN R** |
| `C2_AUX_OUT_11` | `DAC_11` (the MAIN R XLR) | `DAC_13` | the two slots Main Out 1/2 vacate; a D24 has no aux 11/12 connector either way |
| `C2_AUX_OUT_12` | `DAC_12` (the MAIN L XLR) | `DAC_14` | as above |

**The practical consequence, and the reason this is not cosmetic.** PW's bench
patch is AUX OUTPUT 1 → MIC INPUT 1. Under the old patch AUX 1 left the unit on
the **Aux Out A8** XLR and the Aux Out A1 XLR carried aux 8, which was silent.
That is sufficient on its own to explain S39-6 — "the DSP side is proven good
from the strip to the TX DMA buffer, and MIC 1 hears nothing" — with no analog
fault anywhere. The DAC was converting; the signal was leaving on a connector
nobody had a cable in.

## 5. What is NOT settled here — the defs questions

1. **What are `C2_MAIN_OUT_03/04` on a D24?** They are two of the crossover's
   four outputs and they sit on `DAC_15/16`, which are the **Monitor Out** TRS
   jacks. Either the crossover's 3rd/4th outputs are the monitor feed by
   design, or the monitor feed should come from `C2_MON_OUT` and these two
   should be silent on a D24. S42 changed neither.
2. **What feeds the Centre/LF XLR (`DAC_14`, analog J55, block `SUB_W`)?**
   `C2_SUB_OUT` exists and goes to `NET_OUT_01` — a network lane, not a
   connector. On the face of the schematic the sub output belongs on `DAC_14`.
3. **`C2_MON_OUT` is on the codec's talkback-speaker pair** (`CODEC_OUT_1/2`),
   not on the Monitor Out jacks. Two different things are called "monitor".
4. **The headphones (`DAC_09/10`) have no DSP source node at all.** Nothing in
   the graph drives `PHONES_L/R`. A D24 with a headphone jack needs one.
5. **Aux 9–12 have no D24 rear connector** (`d24-io.csv` defines Aux Out A1–A8
   and four paired TRS alternatives, and nothing else). They are addressable
   and parked; `C2_AUX_OUT_12` now lands on the Centre/LF XLR, which is a park
   with a consequence if anyone opens aux 12.
6. **`C2_MAIN_ST_OUT` is on `B_O3`, which has no D24 sink by design** (resolved
   2026-07-31). It is live and unhearable on a D24 and that is correct; it is
   the D32/future main DAC lane, and LOGIC captures the same lane's slots 2–7
   for the Pi's return.
7. **This table is D24 copper.** One firmware serves D24 and D32
   (`dsp4-architecture-decisions.md` D3), so when the D32 analog board lands,
   the output patch becomes product config and `AUX_DAC`/`MAIN_OUT_DAC` is
   where that split goes. Today it is one table serving one board.
8. **`docs/d24-signals.csv` still carries `DAC_nn (assumed)`** on all sixteen
   `OUT_nn_HOT`/`COLD` rows. With the DSP side now compensating the reversal,
   those rows should read `DAC_(9−nn)` and the "NOT proved by the netlist" note
   should go — it is proved, twice.

## 6. How to check any row of this table without a scope

Every row is falsifiable at the bench in one reading, because the DSP end is
readable over the parameter link and the connector end takes a meter:

1. open exactly one output (e.g. `Aux001Level001` at unity, everything else
   muted) and put a known signal on it;
2. `tools/pi/dsp4_s42_align.py` prints which TX table entry carries it and at
   what level;
3. measure the named connector. If the level is at the named connector, the
   row is right; if it is at a different one, the row names which.
